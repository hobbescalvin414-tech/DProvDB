# 扩展实现与解释边界

唯一新增的 Scala 文件是 `src/main/scala/Experiments/FiveDatasets.scala`。入口内部继承 `State`，覆盖 `setupViews` 的 adult/tpch 名称白名单；其余机制、查询生成器、调度器、随机数包装和预算换算保持原样。独立 schema 指向五个新增数据库，每个库只有 `records` 表。原 reproduction 目录和原 Adult/TPC-H 数据库不变。

## 冻结参数与必要调整

- RRQ 原端到端设计保持每分析者 4,000 条、两分析者权限 1:4、五预算、两调度、五方法、四轮。
- 五个连续字段统一缩放 `[0,1000]`，每字段沿用 50 桶。转换保留小数，输入分布不会被均匀化。`prepare_data.py` 记录公开数据观测边界，这不等于在私人数据上免费估计边界。
- BFS 采用 5 叉树、粒度 2，域宽 1000→200→40→8→1.6，最后一层不生成，因此每分析者 1+5+25+125=156 个候选，两人共 312。阈值为 N 的 1%，与数据规模匹配；预算仍为 200，四方法四轮。粒度改变是新值域适配，并未缩减配置组合。
- BFS 精度要求依原实现的 DFS 赋值顺序从 24,900 降至 9,400，而实际执行是 BFS，不能称为执行顺序下单调收紧。
- 预建视图每进程只做一次，各配置刷新原始直方图并重建机制；原始直方图复用不代表跨配置复用带噪缓存。单独记录一次初始化耗时，CSV 重复出现该值，不相加。BFS 候选总数纠正原 CSV 再乘分析者数的错误，只影响扩展输出。
- RRQ 接收数主要由值域、桶数、精度要求、权限和调度决定，未执行最终答案误差统计。统一几何结构可能产生跨数据集完全相同的 RRQ 接收数，不能据此宣称数据分布无关。

## 继承的限制

继承 [原源码审计](../../../reproduction/source-audit.md)：Chorus/ChorusP 实际用 Laplace 加噪，预算换算用 Gaussian 校准；范围覆盖桶数传入直接 COUNT 的敏感度，可能令基线偏保守；噪声源没有统一固定种子。`avgAccuracy` 是已回答查询的请求方差平均值，不是实际 MSE。默认总 delta=1e-5，对 Diabetes 和 Covertype 大于 1/N；本次保留并披露。

另外在扩展审查中发现以下既有行为，未修改，也不把统计一致性检查包装成隐私证明：

1. `Model/View.scala` 使用 `histogramView.values.toList` 生成 `_flatTable`，`queryAnswering` 则按数字桶下标访问列表。Scala Map 的遍历顺序不保证等于 0..49 的桶序，因此基于视图的 BFS 区间答案存在错桶风险。保存的 `raw/histograms.csv` 按显式桶键导出，分布图本身不受此问题影响。
2. `WorkloadUtils.TreeBuild` 设置 `_domains`，未设置 `_rlb/_rub`；`ViewUtils.getSensitivity` 遇两个默认零值返回 1。这会忽略 BFS 跨多个桶的噪声方差累积。BFS 的 SQL 使用严格开区间，直方图按整桶映射，二者也不是精确等价。
3. BFS 的根节点子树由调度器直接入队；树展开与终止仍沿用原逻辑。回答数是该实现执行轨迹，不是正确密集区域发现率或查询精度达标率。
4. `AdditiveGM.checkConstraints` 可在检查分析者行约束前返回 `Cache`。最终 `epsilon_low/epsilon_high` 可超过按权限分配的个人额度；全局账本不超预算不能证明个人约束满足。本次保留各分析者账本，明确不声称所有约束通过。
5. `System.execute` 在 BFS 拒答时缺少空 synopsis 防护。本批次保留较宽松预算 200，以全套实际完成日志验证没有触发该路径，不代表修复。

因此课程报告的可信结论是：公开全量数据接入成功、配置跑全、缓存/调度/预算在现有代码中的实际表现和已发现的工程限制。不能从这些实验推出新的 DP 证明、真实答案误差优势或无偏的算法胜负。
